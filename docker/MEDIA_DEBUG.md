# Диагностика распознавания вложений MAX

Включена по умолчанию. После установки нового кода пересоберите мост:

```sh
docker compose up -d --build bridge
```

Снимки: `data/media-debug/<идентификатор чата>/<время UTC>.*` на хосте
(`/data/media-debug` в контейнере). Путь каждого нового JSON выводится в лог
с пометкой `MAX media debug`.

- JSON: результат парсера для каждого сообщения в опрашиваемом хвосте,
  HTML пузыря, его текст, медиаэлементы, адреса, классы родителей и состояние загрузки.
- HTML: вся страница для проверки селекторов.
- PNG: видимая область страницы на момент снимка.

Снимки создаются при изменении диагностических данных, не чаще раза в минуту.
На чат хранится до 20 комплектов. Это периодические снимки, а не запись каждого
события: быстро появившееся и исчезнувшее состояние может не попасть в историю.
Отладка не меняет распознавание или отправку сообщений и не пересылает старые сообщения.
Ошибка записи снимка не прерывает обработку сообщений.

Настройки в `.env` (применяются при пересоздании контейнера):

```dotenv
MAX_MEDIA_DEBUG=true
MAX_MEDIA_DEBUG_INTERVAL=60
MAX_MEDIA_DEBUG_KEEP=20
MAX_MEDIA_DEBUG_DIR=/data/media-debug
```

Для короткого воспроизведения можно уменьшить интервал до 5 секунд.
Для выключения задайте `MAX_MEDIA_DEBUG=false`.

В JSON сравните `parsed` с `dom.media` и `dom.html`.
`not_recognized` означает, что парсер вернул `None`.
`text_with_media_candidates` означает текст при наличии потенциальных медиаузлов;
это подсказка для проверки, а не доказательство ошибки (например, эмодзи тоже бывают img).
Сравнение последовательных снимков помогает заметить позднюю загрузку вложения.
Файлы содержат переписку и адреса вложений; передавать для анализа можно только нужный комплект.

Старые `tmp/debug_messages_info_1.html` и `.png` остаются на диске, но больше
не перезаписываются каждым опросом. Методы ручного дампа в MaxClient сохранены.

При таймауте ожидания `.bubble` снимок сохраняется даже без сообщений.
В JSON будут `reason: "bubble_wait_failed:TimeoutError"`, текущий `page_url`
и пустой список `messages`. HTML и PNG позволяют отличить экран входа,
загрузку и изменение разметки MAX. Если элементы исчезли после ожидания,
причина будет `no_bubbles`.

Простой `restart` не обновляет Python-код, скопированный в образ через Dockerfile.
После переноса изменённых файлов на сервер требуется `docker compose up -d --build bridge`.
